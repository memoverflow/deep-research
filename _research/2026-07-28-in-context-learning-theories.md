## 故事从这里开始

2020 年夏天，OpenAI 放出了 GPT-3 的论文，标题起得很直接：《语言模型是少样本学习者》。论文里有一个演示，很多人第一次看到时都愣住了：你在输入框里打几个"英语翻法语"的例子，比如

```
sea otter => loutre de mer
peppermint => menthe poivrée
plush girafe => girafe en peluche
cheese =>
```

模型接着就会吐出 `fromage`。这看起来没什么了不起——直到你想起一件事：GPT-3 在看到这段输入的整个过程里，**权重一个字节都没有更新**。没有反向传播，没有梯度下降，没有优化器在后台跑。你给它的只是一段文本，模型做的只是它一直在做的事情：预测下一个词。

这就是所谓的"in-context learning"（上下文学习，简称 ICL）。它诡异之处在于,过去几十年机器学习的整套范式都建立在一个假设上——"学习"就等于"调整参数"。你想让一个模型学会新任务，标准做法永远是：准备数据、算损失、反向传播、更新权重，一步一步把任务"刻"进网络里。而 ICL 完全绕开了这套流程。模型的参数被冻结在那里，你唯一能做的操作是往输入框里多打几行字——然后模型就表现得"好像"学会了这个任务。

这不是一个无关紧要的小把戏。它是今天几乎所有大模型应用的地基：你写的每一条 prompt、你给模型看的每一个示例、Chain-of-Thought 里那些引导性的推理步骤——本质上都是在利用 ICL。但一个尴尬的事实是：**直到今天，学术界对 ICL 到底是怎么工作的，仍然没有一个所有人都认可的答案**。这篇文章要做的，是把几种最重要的理论解释摆在桌面上，看看它们各自讲了一个什么样的故事,以及这些故事之间是怎么打架、又怎么可能同时成立的。

## 先把问题问对：ICL 到底奇怪在哪

在往下讲理论之前，有必要先讲清楚为什么这件事真的值得大惊小怪，而不是"模型很聪明"这种模糊的赞叹带过去。

如果你熟悉元学习（meta-learning）的历史，你可能会说：这没什么新鲜的，MAML（Model-Agnostic Meta-Learning）之类的方法早就能做到"用几个样本快速适应新任务"了。但这里有个关键区别：MAML 是被**专门设计和训练**成"要在少样本上快速适应"的——它的训练目标里直接包含了"内循环梯度更新"这个步骤，模型的架构和损失函数都是为这个目的量身定制的。

GPT-3 完全不是这样训练出来的。它唯一的训练目标是"预测互联网文本里的下一个词"。没有人告诉它"你以后要在测试时看几个例子就学会新任务"，这不是它被优化的目标。ICL 是一个**训练目标里完全没有出现过、却自发涌现出来的能力**。这才是让研究者们抓耳挠腮的地方：一个只是被要求"预测下一个字"的系统，怎么就自己发展出了某种类似"学习算法"的东西？

更让人不安的是几个实验观察：
- **样例的顺序会显著影响结果**——同样的几个例子，换个顺序摆，模型的表现能差出十几个百分点。一个"真正在学习"的系统不应该对样本呈现顺序这么敏感。
- **随机打乱示例里的标签，性能只是略微下降**——2022 年 Sewon Min 等人的论文《Rethinking the Role of Demonstrations》做了一个刺激的实验：把示例里"输入-输出"的对应关系完全打乱（比如把"这部电影很好看 → 正面"改成"这部电影很好看 → 负面"这种错误标注），模型的表现居然只是略微下降,远没有崩溃。这跟传统监督学习的直觉完全相反——如果你拿错误标签去训练一个分类器，它应该会学坏,但 ICL 好像并不是这样"学"标签映射的。

这些奇怪的现象说明：ICL 可能根本不是我们熟悉意义上的"学习"。它更像是模型在利用示例做某种**推断**或**检索**，而不是在做梯度更新那种意义上的"训练"。这就是为什么需要多种理论从不同角度切入。

## 理论一：模型在前向传播里偷偷做梯度下降（隐式优化假说）

### 问题是什么

第一种理论试图给出一个最直接、最"机械"的答案：如果 ICL 看起来像学习，会不会是因为 Transformer 的前向传播——也就是一层一层地做矩阵乘法和注意力计算——本身就在模拟某种优化过程？换句话说，模型的权重是"外层"训练出来的固定参数，但当它读到 prompt 里的示例时，它的**激活值**（activations）在层与层之间的变化轨迹，恰好等价于对一个"内层"小模型做了几步梯度下降。

这个想法被称为"mesa-optimization"（意思大致是"内嵌的优化器"，mesa 在这里取"高台"之意，暗指一个优化过程建立在另一个优化过程之上）。

### 直觉：核心想法

想象你在训练一个"教练"，教练的任务是看几个学生练习网球挥拍的视频，然后现场给出改进建议。你没有直接告诉教练"网球的物理原理是什么"，你只是让他反复观看大量比赛录像去学"怎么当好教练"这件事本身。但训练到位之后，教练在现场看到一个新学员挥拍时,他脑子里其实在飞速地做一件事:根据这几次挥拍的反馈，隐式地在心里更新一个关于"这个学员的问题在哪"的小模型——这个过程发生得极快，你看不到教练在"训练"什么,但他大脑内部的计算过程,可能真的等价于在做一次简化版的分析和调整。

von Oswald 等人在 2022 年的论文《Transformers Learn In-Context by Gradient Descent》做的,就是把这个直觉钉死成一个数学等价关系。他们证明:对于一个只有线性自注意力层的简化 Transformer,在做线性回归这类任务时,存在一组具体的注意力权重,让这一层自注意力的计算,数学上**完全等价**于对一个内部线性模型做一步梯度下降。

### 技术细节（选读）

线性回归想学的是一个映射 $y = w^Tx$，梯度下降更新权重的公式是：

$$w \leftarrow w - \eta \sum_i (w^Tx_i - y_i) x_i$$

这个公式翻译回人话：每次更新，都是把"预测值和真实值的差"乘上"输入本身"，累加起来，去修正当前的权重猜测——差得越多修正越大。

von Oswald 等人证明的是：如果把训练样本 $(x_i, y_i)$ 当作 Transformer 的 in-context 输入，存在一组注意力矩阵 $W_K, W_Q, W_V$，使得单层线性自注意力对查询 $x_{\text{test}}$ 的输出，正好等于"先用 $(x_i,y_i)$ 对 $w$ 做一步梯度下降，再用更新后的 $w$ 去预测 $x_{\text{test}}$"这整个过程的结果。也就是说,注意力机制里的 Query、Key、Value 矩阵乘法，可以被解读成"隐式地在算梯度、隐式地在更新一个内部权重"。

这篇论文还有一个更狡猾的发现:真正训练出来的 Transformer,并不是完全照抄一次朴素梯度下降就收工了——它学到的东西比一步梯度下降更强,论文里称之为"曲率修正"(curvature correction),相当于它自己发现了比标准梯度下降更聪明的更新方式。这暗示 Transformer 不只是"模拟"了一个已知算法,它可能在训练过程中自己发明了一个比人类手写算法更好用的变体。

这个理论也给了此前一直很神秘的"归纳头"(induction heads)现象一个新的定位:此前 Anthropic 团队发现,小模型里有一类专门"复制上文中出现过的模式"的注意力头,对 ICL 至关重要。von Oswald 等人指出,归纳头式的"复制上一次类似情况下发生了什么"，其实可以看成是这种梯度下降式内层优化的一个特殊简化版本——不是巧合,是同一个更普遍机制在不同任务复杂度下的两种表现形式。

## 理论二：模型不是在"学"，是在"定位"一个它早就会的概念（贝叶斯推断假说）

### 问题是什么

第一种理论有一个隐含假设：模型面对示例时,真的在**构建**某种新东西（一个内部权重、一个临时函数）。但另一批研究者提出了一个几乎相反的角度：如果模型根本没有在构建任何新东西呢？如果预训练阶段早就把几乎所有它需要的"任务"都学过了,ICL 只是在**从记忆里把对的那个挑出来**?

这个想法能解释一个此前很难解释的现象:为什么随机打乱示例标签,ICL 表现只是略微下降。如果模型真的是在从示例里"学习"输入到输出的映射关系,乱标签应该造成灾难性破坏——但如果模型只是在用示例的**风格、格式、话题**去定位一个它早已在预训练时见过的"概念",那么就算标签是错的,那些格式和话题信息依然在,模型照样能大致定位对方向。

### 直觉：核心想法

想象你去一个巨大的图书馆找一本书,但你不知道确切的书名——你只记得几个模糊的线索:这本书大概是讲二战历史的、封面是蓝色的、作者姓氏好像是 M 开头。图书馆员（也就是语言模型）看到这几条线索之后,不是在"学习"一本新书要怎么写,他是在用这几条线索去**定位**书架上已经存在的那本书。ICL 的示例,起到的就是这几条模糊线索的作用——它们不是在"教"模型一个新任务,而是在帮模型从预训练时已经内化的海量"概念"里,把最匹配当前情境的那一个检索出来。

Sang Michael Xie 等人 2021 年的论文《An Explanation of In-context Learning as Implicit Bayesian Inference》把这个直觉严格化了。他们的核心假设是:语言模型在预训练时看到的海量文档,并不是杂乱无章的字符串,每篇文档背后都有一个隐含的"主题"或者"风格"（论文里称之为 latent concept，潜在概念）在支配这篇文档里所有词的生成方式。一篇讲金融新闻的文章和一篇写莎士比亚风格情诗的文章,背后对应着截然不同的"概念"。模型在预训练阶段,其实是在隐式地学习"给定一段文字,这段文字最可能是由哪个潜在概念生成的"这个推断问题——这本质上就是贝叶斯推断:根据观测到的证据（prompt 里的文字）,去更新对"隐藏原因"（任务是什么）的信念。

### 技术细节（选读）

用贝叶斯的语言重新描述一下 ICL 发生的过程:模型看到 prompt $\text{prompt} = (x_1, y_1, \dots, x_k, y_k, x_{\text{test}})$，它要做的事情是:

$$p(y_{\text{test}} \mid \text{prompt}) = \int p(y_{\text{test}} \mid x_{\text{test}}, \theta) \, p(\theta \mid \text{prompt}) \, d\theta$$

这个公式翻译回人话就是:模型对测试样本的预测,是把"在每一种可能的潜在概念 $\theta$ 下应该怎么回答"这件事,按"这个 prompt 有多大概率对应这个概念"作为权重加权平均起来。当 prompt 里的证据足够强、足够一致地指向某一个概念时（比如所有示例都在做情感分类）,这个加权平均就会高度集中在那一个正确的概念上,模型的输出因此显得"学会了"这个任务——但它其实全程没有创造任何新东西,只是把注意力锁定在了预训练阶段已经存在的某个"技能"上。

这个理论的漂亮之处在于,它能自然地解释很多此前难解释的现象:
- **随机标签影响不大**——因为示例的格式、话题风格这些信息依然能帮模型定位到"这是个分类任务、大概是情感相关"这个概念,标签本身只是众多定位线索里的一个,不是唯一线索。
- **顺序敏感性**——如果模型在做的是一种序列化的推断更新（类似隐马尔可夫链的状态转移）,那么示例呈现的顺序自然会影响推断的中间状态,顺序敏感反而是这个理论**预测**出来的结果,而不是需要额外解释的反常现象。
- **规模越大 ICL 越强**——更大的模型在预训练阶段见过的文档、内化的"概念"库更丰富,定位起来自然更准。

Xie 等人为了验证这个理论,专门构造了一个叫 GINC（Generative In-Context learning Dataset）的小规模合成数据集,里面的文本是由若干个隐马尔可夫模型（HMM）混合生成的,每个 HMM 对应一个"隐藏概念"。在这个可控的实验环境里,他们证明了即使 Transformer 和 LSTM 都没有专门为 ICL 设计过,只要预训练数据具有这种"每篇文档背后有隐藏主题"的长程一致性结构,模型就会自发涌现出 ICL 能力——这是对贝叶斯框架最直接的实证支持。

不过这个理论也有明显的局限:它主要在小规模合成数据、相对简单的分类任务上得到了验证,面对真实世界里那些需要真正"组合"信息（比如把两条从未在训练数据里同时出现过的规则拼在一起）的复杂任务时,单纯的"检索已有概念"似乎不太够用——这也正是理论一（隐式优化）想要补上的那块拼图。

## 理论三：模型把示例压缩成了一个"任务向量"

### 问题是什么

前两种理论虽然出发点不同,但都还停留在比较抽象的层面——"隐式做优化"或者"隐式做推断"都没有指出:在 Transformer 内部,究竟是**哪个具体的计算环节**在承担这个功能?有没有办法直接打开模型内部,指着某个具体的向量说"看,这就是模型对当前任务的理解"?

### 直觉：核心想法

Roee Hendel、Mor Geva 和 Amir Globerson 在 2023 年的论文《In-Context Learning Creates Task Vectors》给出了一个非常具体、可操作的回答。他们的核心发现是:当模型读完 prompt 里的示例、还没开始处理真正的测试输入之前,模型内部会在某个中间层,把"这批示例究竟在教我做什么任务"这件事,压缩成**一个固定长度的向量**——就像你看了三张"猜谜"卡片之后,脑子里迅速凝结出"哦,这是让我做同义词转换"这一个念头,然后把这个念头存进短期记忆,接下来遇到新的题目,你就直接调用这个念头去解题,不需要每次都重新翻回去看那三张卡片。

这个"任务向量"最有意思的地方在于它的**可迁移性**:研究者们把这个向量从处理示例的那个位置提取出来,然后手动"嫁接"到一个完全没有看过任何示例、只拿到测试输入的全新 prompt 上——模型照样能正确完成任务。这证明了任务向量不是一个偶然的统计噪音,它是模型内部真实存在、承载了"任务是什么"这个信息的一个具体的、可操作的对象。

### 技术细节（选读）

用符号表达一下:设 $S$ 是示例集合、$x$ 是测试输入、$f$ 是 Transformer 的完整计算。Hendel 等人发现,存在一个函数 $\boldsymbol{\theta}(S)$（从示例集合压缩得到的一个向量,维度和模型隐藏层维度相同）和一个更小的函数 $g$，使得:

$$f(S, x) \approx g(x, \boldsymbol{\theta}(S))$$

这个式子翻译回人话就是:模型处理"示例+测试输入"这整个复杂 prompt 得到的输出,几乎完全等价于——先把示例压缩成一个向量 $\theta(S)$,然后只需要这一个向量加上测试输入本身,就足以生成同样的答案，不再需要原始示例文本本身参与后续计算。示例的具体文字内容,在压缩之后就"用完了",接下来的计算只依赖这个压缩后的摘要。

这跟另一支相关研究——Eric Todd 等人提出的"function vectors"（函数向量）——讲的其实是同一件事的不同侧面。Todd 等人进一步定位到:这个任务向量的形成,主要是由 Transformer 里**一小部分特定的注意力头**负责的,他们管这些头叫"function vector heads"。如果你在推理时人为地屏蔽掉这几个头,模型的 ICL 能力会显著下滑;如果你把从一个任务里提取出的函数向量,强行加到另一个完全不相关的 prompt 的激活值上,模型会开始执行原来那个任务——即便你没给它看任何示例。这相当于给理论提供了机制层面的证据:ICL 依赖的,确实是模型内部一小群"专职做任务识别和压缩"的组件,而不是整个网络均匀参与的模糊过程。

任务向量假说和前两种理论并不矛盾,反而可以把它们串起来看:贝叶斯框架告诉你模型在**做什么**（在众多预训练学到的"概念"里定位一个）,任务向量框架告诉你这个定位的结果**存在哪里**（压缩成中间层的一个具体向量）,隐式梯度下降框架则试图解释这个定位和后续应用的过程**是怎么被计算出来的**（通过类似优化更新的注意力计算模式）。三者更像是从不同放大倍数在看同一台显微镜下的样本,而不是三个互相打架的答案。

## 这意味着什么

把这几种理论放在一起看,能得到一个相当有意思的图景:In-context learning 大概不是一个单一的、干净的算法,而是**多种机制叠加**的结果——在简单的、规律清晰的任务上（比如格式固定的分类）,贝叶斯式的"概念检索"可能占主导;在需要一定程度组合、推理的任务上（比如线性回归、少许算术）,类似梯度下降的隐式优化机制可能在起更大作用;而无论哪种机制在起作用,它们的中间产物很可能都会以"任务向量"这种压缩表示的形式,暂存在模型的某个中间层里,供后续的计算调用。

这件事对普通使用者其实有实际的指导意义。如果 ICL 部分依赖"检索预训练已有概念",那就解释了为什么给模型的任务如果**离预训练分布太远**（比如让它做一个训练数据里几乎不会出现的、非常反常识的映射规则）,即便你给再多示例,表现也可能不如给它一个训练数据里常见的任务;如果 ICL 部分依赖"隐式优化",那就解释了为什么**示例的信息量和一致性**（而不只是数量）对效果影响很大——几个高质量、逻辑清晰的示例,可能比十几个杂乱重复的示例更有效,因为后者提供的"梯度信号"更嘈杂。

更深一层的意义在于:如果 Transformer 的前向传播真的能够——即使是隐式地——模拟出某种优化算法,这个事实本身就在提示我们,神经网络"内部"可能远比我们从外部观察到的行为要丰富得多。模型的权重被训练固定之后,它并没有停止"计算出新的功能",只是这种计算发生的场所从"权重更新"转移到了"前向传播中的激活值流动"里。这跟人类专家在面对新问题时,不需要重新学一遍所有基础知识,而是能迅速调用已有的知识框架"现场组装"出一个解决方案——某种程度上有着不谋而合的相似性。这种相似性是否只是表面的类比,还是指向了某种更深的、关于"智能到底是什么"的共同结构,目前还是一个开放问题。

## 下一篇预告

这个系列已经写到了第 57 篇。如果 ICL 真的依赖模型内部一小群"专职识别任务"的组件（就像 function vector heads 那样),这就自然引出一个更根本的问题:大模型内部到底是怎么组织"知识"和"能力"的?是每个概念都有一个专属的、可以被单独定位和操作的神经元或方向,还是说这些表征天然就是叠加、纠缠在一起的?这正是机制可解释性（mechanistic interpretability）这个领域近几年最核心的争论之一——如果你对"打开黑箱、看看模型内部到底在算什么"这件事感兴趣,那会是一个值得深挖的方向。
